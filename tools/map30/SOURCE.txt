 1. Root (builder_template.luau): the map builds under Workspace.Maps.<NAME> (Workspace.Maps is created if
    missing). Only Maps.<NAME> is destroyed and recreated; the stock Workspace.Map and other maps are untouched.
 2. Readiness (builder_template.luau, build_plan.py): on the root, MapBuildErrors = number of warned failures
    (terrain FAILED + each failed instance), then MapBuilt = true; then workspace attribute
    MapBuilt_<NAME with every char outside [A-Za-z0-9_] replaced by "_"> = true (Roblox attribute names allow
    only those characters, so DINO-4 -> MapBuilt_DINO_4; build_plan.ready_attribute() is the rule). That
    attribute is set false when a build starts. The unscoped workspace MapBuilt is no longer set.
    "[30MAPS] DONE ..." is unchanged and still the last log line; a warn precedes it when errors > 0.
    MapBuilt means finished, not succeeded: check MapBuildErrors == 0.
 3. Lighting (builder_template.luau): a plan lighting block is never applied (logged once, then dropped, which
    also keeps lights.on and lighting.water out of PointLights and Terrain water). SkyRally owns Lighting
    through LightingProfiles. applyLighting stays defined but is never called.
 4. Spawn (builder_template.luau): no SpawnLocation is moved or resized; Spawn markers are counted and logged.
 5. Templates (builder_template.luau): ServerStorage.30MAPS_Templates.<NAME>, destroyed and recreated before
    the build makes any template (stock made a new 30MAPS_Templates folder on every run).
 6. Project (build_plan.py): the generated rojo project sets no Workspace.StreamingEnabled and has no
    SpawnLocation (it still sets Lighting.Technology = ShadowMap and mounts ServerScriptService.MapBuilder;
    it is the P2 smoke-test project, not the game project).
 7. terrain.cell (build_plan.py): optional, default 4 (stock raised KeyError in the summary print after the
    outputs were written). The "terrain" key stays REQUIRED as on aa9a451; a map without ground passes
    {"nx": 1, "nz": 1}, which the builder skips with no Terrain side effects.
 8. CLI (build_plan.py): --out, --project and --name are required (stock defaults write into the compiler's
    own tree, here tools/, and the stock name is the plan stem, "plan" for map/<key>/plan.json). The summary
    prints the root, the readiness attribute and what was ignored.
 9. Plan checks (build_plan.py): null groups/markers/labels read as empty lists; a non-list, a marker that is
    not an object, a Checkpoint/Objective/Teleport marker without a numeric p [x,y,z] (or with a name/index
    that is not a string or number), and a label without a string text and p [x,y,z] exit before anything is
    written. The builder reads these outside any pcall, so stock stopped the Script before readiness was set.
10. Header path (build_plan.py): the builder header names the plan by its repo-relative path (absolute only
    for a plan outside the repo), so a committed builder is the same from every checkout.
11. Terrain bake (builder_template.luau, build_plan.py; perf pass 2026-10-19): build_plan.py stamps TERRAIN_HASH
    (sha256 prefix of the template's terrain code, see 12, plus the packed terrain block). When ServerStorage.TerrainBakes.<NAME> is
    a TerrainRegion whose TerrainHash attribute equals it, the terrain step pastes it at the step's minimum cell
    (PasteRegion, empty cells included) instead of running the chunk loop; colours, water look and Decoration are
    still applied as before. Any other bake is ignored with one log line and the terrain builds as on aa9a451. The
    root gets TerrainHash, TerrainBaked and (with terrain) TerrainCellMin/TerrainCellMax (inclusive voxel cells),
    which tools/bake_terrain.py reads to copy exactly the voxels the loop writes.
12. Boot time (builder_template.luau, build_plan.py; V1 D1 2026-10-22): the instance loop yields after YIELD_SLICE
    (0.1 s) of work instead of after every 50 instances (each yield is a whole server frame, 0.1-0.15 s while a map
